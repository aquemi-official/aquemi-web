Workflows

Every change

  1. Find the tool: python tools/studio.py about (or the cards above) says what each reads and writes.
  2. Edit sources only (content/pages/, design-system/, assets/src/, studio/). Never edit a generated file.
  3. See what went stale: python tools/studio.py status.
  4. Refresh it: python tools/studio.py refresh (or name tools: refresh sections guide). It runs the generators in order and then both checks.
  5. Commit and push to dev; promote dev → staging → main by pull request.

Before you push

python tools/specimens.py snapshot     # after page edits
python tools/design_system.py build    # every generated file, the studio bar included
python tools/design_system.py check    # design-system rules
python tools/studio.py check           # studio rules and a dry-run release of the live site

Release the live site

  1. Review the live preview: main, released, exactly as the public would see it.
  2. In studio/manifest.json set "release": {"production": false} and promote to main.
  3. The Pages workflow then publishes the released site at the root and keeps the tooled copy of main at studio/. Nothing is deleted from the repository.

Locally: python tools/studio.py release ../aquemi-live writes the live site to a folder, and fails on any studio file or broken link left in it.
