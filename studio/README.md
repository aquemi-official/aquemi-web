# Aquemi studio

The studio is every development tool that sits beside the Aquemi website: the design system guide, the section library, design research, the media gallery, the page history and the draft tools on the site itself. It is one family with one registry and one switch. It keeps serving design and development on every development copy, and it is detached from the live site when the site goes public.

Open it at `studio.html` (the hub), or from the bar across the top of the site and every tool page.

## How it fits together

```
studio/manifest.json ──► studio/studio.js   the studio bar on every page   (generated by design_system.py build)
        │            ──► studio.html        the hub: tools, copies, workflows, skills
        │            ──► tools/studio.py    about · status · refresh · check · release · assemble
        │
        ├─ tools     one entry per tool: page, what, when, sources, outputs, run, skill, ships
        ├─ release   which published copies carry the studio (true) or are the live site (false)
        ├─ live      live.keep: the only files the live site is made of
        ├─ skills    the Claude Code skills in .claude/skills/
        └─ copies    production, staging/, dev/, live/, studio/
```

| Tool | Page | Generator | Skill | Ships |
| --- | --- | --- | --- | --- |
| Site | `index.html` | `specimens.py snapshot`, `design_system.py build` | aquemi-design-system | live (without the bar) |
| Design system | `design-system.html` | `design_system.py build`, `check` | aquemi-design-system | studio |
| Section library | `sections.html` | `specimens.py snapshot`, `fit`, `restore` | aquemi-design-system | studio |
| Design research | `research.html` | `gallery.py`, `research.py` | image-prompt-loop | studio |
| Media gallery | `inspiration.html` | `images.py`, `gallery.py` | image-prompt-loop | studio, production copy only |
| Page history | `versions.html` | `versions.py` | aquemi-studio | studio, production copy only |
| Studio | `studio.html` | `studio.py` | aquemi-studio | studio |

`python tools/studio.py about` prints the same table in full from the manifest; the manifest wins if this table is ever behind.

## Files

| Path | What |
| --- | --- |
| `studio/manifest.json` | The registry. Hand-written; everything else reads it. |
| `studio/src/bar.js` | Source of the studio bar. The build injects the manifest and writes `studio/studio.js`. |
| `studio/studio.js` | **Generated.** The bar: tool links (current one marked), which copy you are on, and on the site the draft tools (placeholders, open facts, page jump, this page's history). |
| `studio/studio.css` | The bar's styles and the open-facts list. Tokens only. |
| `studio.html` | The hub, rendered from the manifest at load time. |
| `tools/studio.py` | The CLI (below). Standard library only. |
| `.claude/skills/aquemi-studio/SKILL.md` | How agents work with the studio. |

## Commands

```bash
python tools/studio.py about [tool]      # what each tool is, reads, writes; how to refresh it
python tools/studio.py status            # which tools have sources newer than their outputs
python tools/studio.py refresh [tool]    # run the generators in order, then both checks
python tools/studio.py check             # studio rules + a dry-run release of the live site
python tools/studio.py release <out>     # write the live site into <out>
```

`refresh` runs, in order and only what the named tools need: `images.py` and `gallery.py` (need Pillow; skipped without it), `specimens.py snapshot`, `research.py` (only when the `../research` working folder is beside the checkout, since `research.html` holds build notes only that folder has), and `design_system.py build`. `--history` adds `versions.py`, which belongs on an up-to-date `main`.

`check` fails on: a tool page that does not load the bar, a stale `studio/studio.js`, a skill folder not in the manifest (or the reverse), more or fewer than one studio block in `index.html`, anything outside that block reaching the studio, and, in a release dry run, any studio file in the live site, any `live.keep` pattern that matches nothing, or any link in the released pages that points at a file the live site does not have. CI runs it in the required `check` job.

## Detaching for the live site

The site never depends on the studio. `index.html` keeps all studio wiring in one block:

```html
<!-- studio: development tooling (studio/manifest.json). ... -->
<link rel="stylesheet" href="studio/studio.css?v=…">
<script defer src="studio/studio.js?v=…" data-tool="site"></script>
<!-- /studio -->
```

and announces each render with `document.dispatchEvent(new CustomEvent('aq:render', {detail: {page}}))`, which the bar listens for. Placeholders render clean (`is-clean`) unless the bar turns highlighting on. `release` copies only `live.keep` and cuts that block: the result is the website and nothing else (about 10 MB against the repository's 480 MB).

Published copies (`.github/workflows/pages.yml`, which calls `python tools/studio.py assemble`):

| URL | What | While `production: true` | After `production: false` |
| --- | --- | --- | --- |
| `/` | main | site and studio (draft) | live site only |
| `/studio/` | main, tooled | not published | site and studio, page history and gallery included |
| `/live/` | main, released | live preview | live preview |
| `/staging/` | staging | site and studio (no history or gallery) | per staging's own `release.staging` |
| `/dev/` | dev | site and studio (no history or gallery) | per dev's own `release.dev` |

Going live: review `/live/`, set `"release": {"production": false}` in `studio/manifest.json` on `dev`, promote to `main`. To undo, set it back. The `noindex` tag on `index.html` is a separate decision: remove it when the site should be found by search engines.

## Adding a tool

1. A page at the repo root that reads generated data. Tokens only.
2. In its head: `studio/studio.css` and `<script defer src="studio/studio.js" data-tool="<id>"></script>`.
3. An entry in `studio/manifest.json` → `tools`. If it is too large for the staging and dev copies, set `production_only` and add its folders to `HEAVY` in `tools/studio.py`.
4. A generator in `tools/` (standard library; docstring lists its commands) and a step in `STEPS` in `tools/studio.py`.
5. `python tools/design_system.py build`, `python tools/studio.py check`, a row in the AGENTS.md file table.

## For agents

- Start with `AGENTS.md`, then this file. Claude Code: the `aquemi-studio` skill covers the studio; it points to `aquemi-design-system`, `image-prompt-loop` and `motion-library` for the work inside each tool.
- Several agents can work at once: each tool's sources are separate files, and every generated file is rebuilt from sources, so whoever commits runs `build` and both checks last.
- Never edit a generated file, never delete a look (retire it), never put a guessed fact into a `[placeholder]`.
- Report skipped `refresh` steps (no Pillow, no `../research`) to the person you work for.
